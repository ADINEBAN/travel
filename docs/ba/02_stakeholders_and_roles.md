# Stakeholders & Roles

| Stakeholder | Trách nhiệm/đóng góp |
|---|---|
| Lecturer/Sponsor | Yêu cầu học phần và phản hồi |
| Product Owner | Quyết định Product Goal, Product Backlog ordering |
| Scrum Master | Hỗ trợ Scrum events và xử lý trở ngại |
| BA | Phân tích, đặc tả, quy tắc và truy vết yêu cầu |
| UX/UI | User flow, wireframe, prototype |
| Developers | Thiết kế kỹ thuật và xây dựng Increment |
| QA/Tester | Test case, test execution |
| End users | Phỏng vấn, usability feedback |

## Phân biệt
- PO: xây gì trước và vì sao.
- BA: nghiệp vụ, yêu cầu, quy tắc, acceptance.
- UX/UI: tương tác người dùng.
- Developers: giải pháp kỹ thuật và triển khai.
- QA: xác minh yêu cầu.
- Scrum Master: giúp Scrum được hiểu và vận hành đúng.

BA là chuyên môn trong nhóm, không phải accountability chính thức trong Scrum Guide.

## RACI đề xuất
R=Responsible, A=Accountable, C=Consulted, I=Informed.

| Đầu việc | PO | BA | UX | Dev | QA | SM |
|---|---|---|---|---|---|---|
| Vision/Goal | A | C | C | C | I | I |
| Interview research | A | R | R/C | I | I | C |
| Requirement spec | A | R | C | C | C | I |
| User flow/prototype | A | C | R | C | C | I |
| Data/API design | A | C | I | R | C | I |
| Acceptance Criteria | A | R | C | C | C | I |
| Implementation | I | C | C | R/A | C | I |
| Test execution | I | C | C | C | R/A | I |
| Backlog ordering | R/A | C | C | C | C | I |

Điền tên thành viên và xác nhận một người A cho mỗi đầu việc.
